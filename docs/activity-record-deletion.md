# API-50 종료 기록 삭제·마지막 완료 성장 취소

> 2026-11-19 통합 계약: [활동 APIv2](api-v2-activities.md) · [코드·명세 대조/후속](activity-contract-status.md). 구현·병합과 운영 반영 상태는 구분한다.

Issue #240, develop eb051f46(#239) 및 APIv2 API-50을 따른다.
`DELETE /api/v1/activity-records/{recordId}`, JWT, HTTP200/RECORD200_6, no-store.

- ACTIVE 회원→본인 나무→본인 기록을 잠근다. PAUSED/ENDED 나무도 허용한다. 타인/없는 기록은 RECORD404_1, 진행 중은 RECORD409_6이다. snapshot 없는 과거 종료 기록도 대상이며 가짜 snapshot을 만들지 않는다.
- 종료 상태·버전·시작 snapshot·피드백·API-29 최초 응답은 보존한다. deletedAt은 DB 서버 시각과 기존 시작/종료/직전 갱신 시각보다 이르지 않은 최초 값이다. 삭제한 행과 불변 삭제 receipt를 같은 트랜잭션으로 저장한다. 본인 DELETE 재요청은 최초 결과 그대로이며 현재 성장 값으로 다시 계산하지 않는다.
- COMPLETED의 비삭제 동종 완료가 남으면 기여를 유지한다. 원본 기록 삭제 시 최소 recordId 생존 완료로 origin 참조와 현재 mirror를 옮긴다. 기여 ID·인정 출처/시각·과거 인정 단계는 변경하지 않으며 처음 원본을 포함한 이전/이후 사실은 불변 감사에 남는다. 다른 기록의 최초 API-29 growthApplied를 고치지 않는다.
- 마지막 완료이면 해당 고유 기여만 취소한다. 남은 기여 수 N과 현재 취미의 기존 k로 storedStage=min(5,floor(N/k)), 현재 단계 진행=N-storedStage*k를 유지한다. 원장 contributionId 순서로 현재 진행 배치만 재계산한다. 과거 credited_stage_number와 별도의 nullable progress_stage_number를 사용하며 null은 기존 배치를 뜻한다. 새 SELF/EXPERIENCE 기여도 같은 집계/검증을 사용한다.
- 대상/전체 원장 origin·mirror·비삭제 완료 pair·현재 단계 기준선이 일치하지 않으면 RECORD409_7로 보존·중단한다. 과거 근거를 추측해서 수정하지 않는다. PARTIAL/NOT_DONE은 성장에 영향을 주지 않는다. 최대 단계에서 남은 누적 기여가 충분하면 최대를 유지한다.
- 삭제·origin 이전/취소·현재 배치·mirror·나무 단계·이전/이후 감사·최초 삭제 응답이 한 트랜잭션이다. 어느 단계 실패든 전체 rollback한다. 회원/나무 잠금으로 완료·삭제·외부 인정 writer를 직렬화한다. 나무 수명주기/슬롯/원본 카탈로그/북마크/예약 상태는 바꾸지 않는다.

## 기존 API 연결

- API-27·28·29는 소유권/삭제 필터를 먼저 적용해 RECORD404_1이며, 삭제된 완료 receipt를 다시 노출하지 않는다. API-30은 페이지 선정 전에 삭제 필터를 적용하므로 삭제된 anchor에도 기존 정렬 키 커서가 이어진다.
- API-18·20·22는 활성 원장과 현재 배치를 공유한다. API-20 현재 활동/최근 활동 시각에서 삭제 행을 제외한다. 단계가 낮아지면 신규 API-26 해금 검사에 적용하며 이미 시작한 다른 snapshot은 계속 진행/완료할 수 있다.
- API-39의 새 인정은 삭제 행을 재사용하지 않는다. 기존 ATTENDED 예약 재전송은 참여 사실을 읽기만 하며 삭제 행 복원/취소 기여 재생성을 하지 않는다. 기록 참조 FK가 없는 과거 재전송도 기존 완료 이력 ID만 확인할 수 있다. 과거 idempotency 응답은 고치지 않는다. 실제 제공자 검증 미연동503은 그대로이며 격리 검사는 내부 TEST ONLY applyAttendance 경로다.
- 현재 코치·추천 요청 구성은 활동 기록 테이블을 직접 조회하지 않는다. 관련 코드 검색으로 확인했으며 새 기록 조회 연결은 추가하지 않는다. 추후 기록 기반 맥락을 추가하면 deleted_at IS NULL을 적용해야 한다. 이미 저장된 대화/추천 응답은 수정하지 않는다.

## V31·운영 경계

V31은 deleted_at, 현재 진행 배치, 불변 삭제/원장 감사와 정합성 trigger를 추가한다. V1~V30과 기존 행·과거 시각/출처/완료 응답은 유지하며 삭제/재배치/가짜 이력을 백필하지 않는다. 삭제 행의 변경·복원과 감사 수정/직접 삭제를 차단하고 기존 회원/나무 purge cascade는 유지한다. ddl-auto=validate를 유지한다.

운영 적용은 하지 않는다. 실제 배포 시 기존 writer/reader를 함께 교체해야 한다. API-50 사용 후에는 삭제 필터·현재 배치를 모르는 구버전 앱으로 단순 복구하면 안 된다. 운영 배포/복구 호환성은 별도 승인과 계획 대상이다. 격리 PostgreSQL17·Redis·테스트 인증만 사용하며 AWS·운영 DB/Secret·유료 모델에 접근하지 않는다. 전역 COMMON429 정책은 별도 플랫폼 후속이다.
