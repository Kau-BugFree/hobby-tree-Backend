# 온보딩 약관 본문과 동의 연동

`GET /api/v1/onboarding/options`는 HTML이 아닌 일반 텍스트 `content`를 제공한다.
프론트는 줄바꿈을 유지해 앱 내부에 표시한다. `contentUrl`은 없다.
본문 원본은 `OnboardingTermsContent.java`이다.
약관 8종 중 6종(서비스 이용약관/개인정보 처리방침/개인정보 수집 및 이용 동의서/위치기반
서비스 이용약관/사진 파일 접근 및 이용 안내/AI 서비스 이용 및 개인정보 처리 안내)은 법무
검토를 거친 실제 초안이며, 운영 주체명·시행일 등 일부 항목은 `[확정 필요]`로 남아 있다.
나머지 2종(만 19세 이상 확인, 학습용 데이터셋 활용 동의)과 `locationConsentNotice`는
여전히 `[개발용 임시 본문]`으로 시작하는 검토용 초안이며, 운영자는 하비트리 운영팀, 문의
이메일은 kauhobbytree@gmail.com이다. 프론트는 이 두 표시 중 어느 쪽이든 생략하지 않고
보여야 하며 운영용 최종 문서로 취급하지 않는다.

## 응답 항목

| 위치 | ID | 제목 | 버전 | 필수 |
| --- | --- | --- | --- | --- |
| terms[] | 1 | 서비스 이용약관 | 2.0 | true |
| terms[] | 5 | 개인정보 처리방침 | 1.0 | true |
| terms[] | 2 | 개인정보 수집 및 이용 동의서 | 2.0 | true |
| terms[] | 3 | 만 19세 이상 확인 | 1.0 | true |
| terms[] | 6 | 위치기반 서비스 이용약관 | 1.0 | false |
| terms[] | 7 | 사진 파일 접근 및 이용 안내 | 1.0 | false |
| terms[] | 8 | AI 서비스 이용 및 개인정보 처리 안내 | 1.0 | false |
| terms[] | 4 | 학습용 데이터셋 활용 동의 | 1.0 | false |
| locationConsentNotice | NEARBY_EXPERIENCES | 위치 정보 이용 동의 | 1.1 | 선택, 별도 API |

목록의 배열 위치를 ID로 사용하지 않는다. ID·버전·isRequired·content를 응답에서 읽는다.
ID는 한번 쓰이면 다른 약관으로 재할당하지 않으므로(이미 저장된 동의 이력의 의미가 바뀌면
안 됨) 배열 순서와 ID 숫자 순서가 일치하지 않는다 - 필수 4종(1·5·2·3) 다음에 선택 4종
(6·7·8·4) 순으로 반환된다.
만 19세 이상은 별도 필수 체크이며 생년월일 기반 성인 본인인증은 아니다.
학습 활용은 기본 미선택으로 표시하고 전체 필수 동의에 묶지 않는다.

## 온보딩 완료 요청

`POST /api/v1/onboarding/complete`

```json
{
  "preferencesVersion": 1,
  "agreements": [
    {"termsId": 1, "version": "2.0", "agreed": true},
    {"termsId": 5, "version": "1.0", "agreed": true},
    {"termsId": 2, "version": "2.0", "agreed": true},
    {"termsId": 3, "version": "1.0", "agreed": true},
    {"termsId": 4, "version": "1.0", "agreed": false},
    {"termsId": 6, "version": "1.0", "agreed": false},
    {"termsId": 7, "version": "1.0", "agreed": false},
    {"termsId": 8, "version": "1.0", "agreed": false}
  ]
}
```

preferencesVersion은 실제 저장한 취향 버전을 사용한다.
termsId 1·5·2·3(필수 4종)의 누락·미동의는 거부한다. 4·6·7·8(선택 4종)은 누락하거나
false여도 완료할 수 있다.
제출한 선택 동의·거부도 user_terms_agreements에 별도 이력으로 저장한다.
구버전 동의는 ONBOARDING409_1로 거부하므로 프론트는 항상 `GET /api/v1/onboarding/options`로
받은 각 약관의 현재 version을 그대로 제출해야 한다 - 위 예시의 버전 값을 그대로 쓰지 말고,
응답에서 읽은 값으로 교체한다.
locationConsentNotice는 기존 위치 동의 API에 버전 1.1로 따로 제출한다.
기존 약관 ID와 과거 동의 이력은 유지하며 DB 마이그레이션은 없다.
취향 선택지 값은 바뀌지 않아 optionsVersion은 2026-11-07을 유지한다.

## 본문에 반영한 정책

- 가입: 만 19세 이상 자기 확인. 서비스 무료, 자체 유료 결제 없음. 구독 도입은 보류.
- 회원 데이터·AI 대화·활동 지역: 탈퇴 후 복구 기간 30일 종료 시 사용자 연결 자료 삭제 정책.
  다만 현재 코드는 30일 복구 기한만 적용하며 종료 후 자동 삭제는 아직 구현하지 않았다는 점을
  본문(서비스 이용약관 11조, 개인정보 처리방침 3조)에 명시했다.
- 위치 철회: 현재 위치 기반 지역 삭제, 직접 선택한 지역 유지. 원시 좌표 미저장 정책.
  위치기반 서비스 이용약관(신설)은 위치정보법 기준 이용·제공사실 확인자료를 6개월 보관하는
  별도 조항(제8조)을 포함하며, 아직 실제 위치기반 추천 기능이 적용되기 전의 초안이다.
- 사진·파일: 이용자가 직접 선택한 파일만 해당 기능 목적 범위에서 접근·처리하며, 선택하지
  않은 파일을 무단으로 열람하거나 수집하지 않는다. 아직 프로필 사진 업로드 등 실제 기능이
  전면 적용되기 전의 초안이다.
- AI: RAG 우선. 무료 Gemini는 가상 데이터 테스트만 허용하고 실제 사용자 연동은 별도 검토.
  AI 서비스 이용 및 개인정보 처리 안내(신설)는 외부 AI 제공업체·처리 국가·모델 학습 활용
  여부를 표로 공개하도록 되어 있으나 해당 항목은 아직 `[확정 필요]`다.
- 학습: 별도 선택 동의자 자료만 개인정보 정제 후 내부 데이터셋에 활용. 외부 공개·판매·기관 제공 없음.
- 학습 동의 철회: 추가 편입 중단 및 미학습 자료 삭제. 이메일 접수, 앱 내 철회는 후속 개발.
- 정책 변경: 앱 내 공지와 필요한 경우 추가 동의.

시행일, 서버 접속·오류 로그 항목·보관기간, 외부 AWS·지도·AI의 구체적 처리 조건,
법정 별도 보관 정보, 위치 이용·제공사실 확인자료, 이미 학습된 자료·모델의 철회 처리 범위는
본문에 '미정' 또는 '[확정 필요]'로 명시했다. 이 문구가 외부 전송·운영 개시의 허가를
의미하지 않는다.

## 구현 범위와 후속 작업

이번 구현은 본문 제공과 필수·선택 동의 검증·이력 저장이다.
탈퇴 후 자동 삭제·데이터셋 구축 및 정제·철회 처리·실제 AI 호출·재동의 알림·구독·운영 고지 등은
본문에 적힌 정책과 실제 코드의 일치 여부를 별도로 확인하고 필요한 기능을 구현해야 한다.
위치기반 서비스 이용약관·사진 파일 접근 및 이용 안내는 해당 기능(위치기반 추천, 프로필 사진
업로드)이 전면 적용되기 전의 초안이므로, 기능을 실제로 켤 때 본문 내용과 실제 동작이
일치하는지 다시 확인해야 한다.
데이터셋 내보내기는 현재 버전의 유효한 동의를 별도 확인하기 전 실행하지 않는다.
모델 학습은 미정인 철회 처리 범위를 확정·안내한 후 진행한다.
본 문구는 미정·확정 필요 사항을 포함한 연동용 초안이며 전체 개인정보 처리방침을 대체하지 않는다.

## 검증

OnboardingIntegrationTests: 본문·연락처·줄바꿈, 필수/선택 구분, 성인 확인 누락·거부,
학습 미동의·동의·생략, 기존 동의 저장·버전 검증을 확인한다.
위치 동의 테스트는 CURRENT_VERSION=1.1로 기존 정책을 회귀 검증한다.
