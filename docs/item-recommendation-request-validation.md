# 준비물 상품 추천 요청 검증

대상: `POST /api/v1/activities/{activityId}/item-recommendations`

## 필터 목록

- `merchantCodes`, `excludeOfferRefs`의 생략·목록 자체 `null`·빈 목록은 기존처럼 빈 목록으로 처리한다.
- 목록 안의 `null` 원소는 `400 ITEMREC400_1`로 거절한다. 예: `merchantCodes: [null]`.
- 기존 원소 개수·길이·공백 검사, 선택적인 예산·가격·catalogRevision의 null 계약을 유지한다.

## AI 전송 크기

AI HTTP 경계는 64KiB이다. BE는 DB에서 가져온 준비물과 사용자의 선택 조건을 조합한
**최종 AI 요청 JSON의 UTF-8 바이트**를 한 번 직렬화하고, 그 바이트를 그대로 전송한다.

| 최종 크기 | 처리 |
| --- | --- |
| 65,536바이트 이하 | 기존 AI 호출 진행 |
| 65,536바이트 초과 | AI에 전송하지 않고 `400 ITEMREC400_1` 반환 |

한글 등 다중 바이트 문자, JSON escape, 필드명·구분자·DB 준비물 내용도 크기에 포함한다.
FE 원문 길이/Content-Length, Java 문자열 길이 또는 필터 글자 수만으로 판정하지 않는다.
필드별 허용 개수·길이를 만족해도 여러 준비물의 필터를 합치면 전체 상한을 넘을 수 있다.
FE는 선택 조건/제외 목록을 줄이도록 안내하며, 동일 요청을 자동 재시도하지 않는다.

이는 AI로 보내는 요청 한도이며 FE HTTP 수신 본문 전체에 적용하는 전역 업로드 제한이 아니다.
클라이언트 비활성 상태의 기존 `503 ITEMREC503_1` 처리는 유지한다.
AI의 예상 밖 413/422 응답은 기존처럼 `502 ITEMREC502_1`로 변환한다.
응답 256KiB 상한·타임아웃·자동 재시도 금지·DB snapshot 트랜잭션 분리는 유지한다.

## 검증 범위

- 필터 null 원소 거절과 AI 클라이언트 미호출, 목록 null/생략·정상 선택값 보존
- 한글 및 quote/backslash를 포함한 최종 JSON 65,535/65,536/65,537바이트 경계
- 실제 loopback HTTP stub 수신 바이트 일치와 초과 요청 무전송
- 공통 예외 응답의 `400 ITEMREC400_1` 및 기존 정상 요청·오류·시간 초과 회귀 검사

참고: 기존 어댑터 Issue #264, 후속 수정 Issue #288.
동기화·이름 160/200자·20개 초과 활동 정책·AI 실행 환경·STT B·운영 적용은 이 변경에 포함하지 않는다.
