Issue #244. 기준은 APIv2.md API-31과 최신 develop b85889f(V32 포함)이다.
`PUT /api/v1/activities/{activityId}/save`의 저장 가능 범위를 API-24/25/33과 맞춘다.

- ACTIVE 회원이 요청한 활동이 PUBLISHED이고, 현재 소속 단계의 취미가 is_supported=true여야 저장할 수 있다.
- 없는 활동·비공개 활동·미지원 취미의 활동은 기존 HTTP404/ACTIVITY404_1로 동일하게 거절한다.
- 이미 저장돼 있어도 현재 공개 조건을 먼저 검사한다. 거절은 북마크·savedAt·콘텐츠·기록·성장을 변경하지 않는다.
- 취미가 다시 지원되면 기존 저장 관계를 재사용하고 최초 savedAt을 유지한다.
- 나무 보유·현재 성장 단계·콘텐츠 실행 단계의 정비 여부를 북마크 저장 조건으로 추가하지 않는다.
- API-32의 비공개/미지원 활동 저장 취소·반복 취소와 API-33의 이용 불가4필드 안내는 유지한다.

## 트랜잭션과 경쟁 요청

기존 회원 쓰기 잠금으로 같은 사용자의 save/unsave를 직렬화하고, findForSaving의 활동 공유 잠금을
트랜잭션 종료까지 유지한다. 소속 취미는 이 트랜잭션 안에서 현재 activity→stage→hobby로 확인한다.

V18의 취미 is_supported 변경과 단계의 hobby_id 이동은 같은 트랜잭션에서 자식 활동을 touch하므로
활동 공유 잠금과 경쟁한다. 이번 수정은 부모 행 잠금을 뒤늦게 추가하거나 기존 잠금 순서를 바꾸지 않는다.
독립 연결의 실제 PostgreSQL 잠금 대기로 다음 순서를 검증한다.

1. 지원 해제 writer가 먼저 활동을 잠그면 save는 기다린다. writer commit 뒤에는404, rollback 뒤에는200이다.
2. 활동 reader가 먼저 공유 잠금을 가진 경우, 지원 해제 writer는 자식 touch에서 기다린다.
   그 사이 save는 종전 지원 상태로 완료할 수 있고 writer commit 뒤 조회는 이용 불가가 된다.
   겹치는 편집보다 앞서 유효했던 저장이며, 후속 저장 요청은404로 거절한다.

외부 writer의 trigger 비활성화·강제 데이터 변경은 이 계약 밖이다. 승인된 콘텐츠 편집 규약은 #130에서 관리한다.

## 변경·검증 범위

SavedActivityService의 공개 조건과 실제 HTTP 회귀 테스트·이 문서만 변경한다.
Repository·Entity·V1~V32·응답/오류 코드·JWT·CORS·운영/배포 설정은 변경하지 않는다.
미지원 신규/반복 저장·저장 시각·지원 재개·부모 이동·저장 취소/목록·동시 writer commit/rollback 및 기존 활동 회귀를
격리 PostgreSQL17/Redis·제한 테스트 역할·테스트 인증으로 확인한다. 수정 전 실패도 별도로 보존한다.

운영 AWS/DB/Secret 조회·배포·마이그레이션·실제 계정/모델 호출은 수행하지 않는다.
공통 COMMON429와 대량 부하 검증, #127의 실제 FE 확인은 별도 후속이다.
